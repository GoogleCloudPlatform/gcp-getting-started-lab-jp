# User Journey Catalog

Test material for evaluating how well coding agents migrate real cloud workloads to GCP — with the `migration-to-gcp` skill (`features/migration-to-gcp/`) or unaided. That plugin ships one vendor-specific skill per source cloud (`aws-to-gcp`, `azure-to-gcp`); the agent under test loads the one matching the journey's source cloud. Each journey is a self-contained fictional-customer source-cloud project. Every AWS journey j1–j5 has a hand-built, deployed, smoke-tested GCP reference implementation (in `user-journey-tests/gcp-references/`, deliberately outside the journey directories) serving as the known-good migration target; j6's reference is pending, and Azure references land as deploy validation completes.

Authoring contract: [`user-journey-tests/CONVENTIONS.md`](user-journey-tests/CONVENTIONS.md).

## How to run an evaluation

```bash
cd user-journey-tests/<vendor>/<journey>/   # agent under test runs HERE (must not see user-journey-tests/gcp-references/)
# install the skill per the journey README, then e.g.:
#   claude --plugin-dir ../../../features/migration-to-gcp
#   > "migrate from AWS to GCP"
# outputs land in .migration/<MMDD-HHMM>/ ; log observations to .iteration-log/iter-N/
```

Score against: (1) phase completion without supervision; (2) inventory completeness vs the journey's resource list; (3) trap handling (each embedded ambiguity surfaced, not silently guessed); (4) generated GCP design vs the reference implementation; (5) parity — the journey's `scripts/smoke-test.sh` passing against the agent's deployed GCP stack, exactly as it passes against `user-journey-tests/gcp-references/<vendor>/<journey>/`'s deployment.
