New `design-refs/agent-runtime.md` placement rubric makes **Agent Runtime on the Gemini Enterprise Agent Platform** (formerly Vertex AI Agent Engine) the default target for detected agent workloads, with a single eliminator (K8s mandate → GKE) — eliminator-redirected workloads map and emit Terraform as normal container workloads. - **`design-refs/agent-governance.md`** (`aws-to-gcp` skill) — AWS→GCP mapping for the controls around a migrated agent, from the GEAP Govern docs + the two Agent Gateway egress codelabs (verified 2026-08-28): **Agent Registry** (catalog + topology; unregistered destinations denied), **Agent Gateway** (Client-to-Agent ingress / Agent-to-Anywhere zero-trust egress, VPC via network attachment), **Agent Identity** (SPIFFE, `--enable-agent-identity`), IAP per-tool authorization (`roles/iap.egressor`, CEL on `mcp.toolName`/`isReadOnly`), **Model Armor** CONTENT_AUTHZ, semantic governance policies. Wired into `agent-runtime.md` (governance annex), the Step 3D runbook (item 9), and the design-refs index.

- **PHP estate support** (`aws-to-gcp` skill, discover → design → generate): Discover now scans `**/*.php` + `composer.json`/`composer.lock`, detects `aws/aws-sdk-php` (`Aws\<Namespace>\<Namespace>Client` incl. `Aws\BedrockRuntime`/`BedrockAgentRuntime`/`BedrockAgentCore*`/`SageMakerRuntime` — verified against the SDK manifest), PHP OpenAI usage (`openai-php/client`, detection-only), LLPhant (`theodo-group/llphant`) as framework/agent signal, PHP model-ID extraction (`invokeModel(['modelId'=>…])`, `$client->chat()->create(['model'=>…])`), Composer auth-SDK exclusions, and Laravel/Symfony/Slim route parsing for `app-routes.json`. New all-language **scan-exclusion rule**: dependency-install dirs (`vendor/`, `node_modules/`, `site-packages/`, …) are never scanned for imports/signals — manifests are the dependency evidence (a committed `vendor/` tree would otherwise false-positive on every `Aws\*Client` class). Generated code patches follow the **PHP support boundary** (BINDING, verified 2026-08-28): official `google/*` Composer packages only — LLM calls via the GA `google/cloud-ai-platform` GAPIC (`PredictionServiceClient::generateContent`) or REST; **no official Google Gen AI PHP SDK and no PHP ADK exist**, so the adapter/design emit a mandatory PHP-support-gap warning for any capability without an official PHP surface (REST or supported-language rebuild offered), community Gemini PHP SDKs are never emitted, and the language router emits `.php` adapters instead of silently falling back to Python. PHP agent workloads are framework `custom` with an explicit custom-container-vs-rebuild trade-off. The **non-AI SDK chain** is wired end-to-end too: `discover-app-sdk.md` extracts PHP call sites (per-service `Aws\<Namespace>\<Namespace>Client` pattern table, Composer manifest confirmation, vendor/ excluded) and `sdk-mapping.md` gains a full PHP section — every mapped service (S3→`google/cloud-storage`, SNS/SQS→`google/cloud-pubsub`, CloudWatch/Logs→monitoring/logging, Secrets Manager, DynamoDB→Firestore/Bigtable (grpc-extension prerequisite noted), KMS, SES→third-party MANUAL, Lambda-invoke→Cloud Run via `google/auth` ID token, EventBridge) targeting official `google/*` Composer packages, all 13 verified present on the `google` Packagist vendor 2026-08-28.

## [1.0.0] -- 2026-04-12

### Added

- **6-phase migration workflow**: Discover, Clarify, Design, Estimate, Generate, and Feedback phases for systematic AWS-to-GCP migration planning.
- **Terraform infrastructure discovery**: Scan `.tf` files for AWS resources, classify by type, cluster by dependency, and compute topological depth.
- **Application code scanning**: Detect AI/ML framework imports (SageMaker, Bedrock, PyTorch, TensorFlow) and map to Vertex AI equivalents.
- **Billing data import**: Parse AWS Cost and Usage Reports (CUR) to enable billing-only migration design when no IaC is available.
- **Adaptive clarification**: Context-aware questions across six categories (global, compute, database, networking, AI, storage) with sensible defaults.
- **Multi-path design**: Infrastructure-based, AI-workload, and billing-only design paths that adapt to available discovery inputs.
- **Cost estimation**: 3-tier estimates (conservative, moderate, optimistic) using web search and a local pricing cache -- no community MCP servers.
- **Artifact generation**: Terraform configurations (`google_*` resources), migration scripts, AI provider adapters, and documentation (`MIGRATION_GUIDE.md`, `README.md`).
- **Redshift specialist gate**: Redshift / `aws_redshift_*` resources flagged for specialist engagement rather than automated mapping.
- **Auth provider exclusions**: Third-party auth SDKs (Auth0, Firebase Auth, Clerk, Okta, Supabase Auth, Keycloak, NextAuth) recognized and excluded from migration scope.
- **Service preferences**: Containerized workloads steered toward Cloud Run and GKE; third-party auth providers preserved rather than replaced.
- **Data-transfer-only one-time costs**: One-time migration costs scoped to AWS data transfer egress fees only -- no human labor estimates.
- **Optional feedback collection**: Anonymized telemetry with survey integration offered after Discover and Estimate phases.
- **Claude Code support**: Plugin manifest, marketplace configuration, and MCP server definitions for Claude Code >= 2.1.29.
- **Gemini CLI support**: Extension manifest and settings configuration for Gemini CLI >= 0.1.0.
- **MCP server integration**: Official `@google-cloud/gcloud-mcp` (Google) and `knowledge-mcp.global.api.aws` (AWS) servers only.
- **30 AWS-to-GCP service mappings**: EC2, Lambda, ECS Fargate, EKS, S3, RDS, Aurora, DynamoDB, ElastiCache, Redshift, SQS/SNS, CloudWatch, Route 53, ALB/NLB, VPC, IAM, Secrets Manager, KMS, SageMaker, Bedrock, CloudFront, WAF/Shield, Step Functions, Kinesis, Glue/EMR, ECR, CodePipeline/CodeBuild, EFS, and Direct Connect.
- **Development tooling**: mise-based build pipeline with markdown linting, dprint formatting, JSON manifest validation, cross-reference checks, and security scanning (Bandit, Semgrep, Checkov, GitLeaks, Grype).
